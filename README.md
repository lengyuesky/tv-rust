# TV Rust

[![检查与镜像发布](https://github.com/lengyuesky/tv-rust/actions/workflows/check.yml/badge.svg)](https://github.com/lengyuesky/tv-rust/actions/workflows/check.yml)

Rust 影视聚合服务与中文 React/TypeScript 网页，兼容 LunaTV 配置和飞牛播放器。网页与飞牛使用同一套家庭账号，同一用户共享收藏、历史与进度。

支持 JSON、Base58 文本、订阅 URL、手动及定时刷新、多订阅源归属和按源启停；首次启动的视频源为空，由管理员导入。管理员的“订阅与视频源”按近 7 天的活跃线路探测显示可用性；至少 3 条线路全部被上游拒绝时提示“服务器无法访问”，不会自动禁用视频源。电影、剧集可聚合搜索、查看详情、选集、播放 MP4/HLS、换源与续播。豆瓣推荐不可用时仍可使用搜索与个人数据。

移除订阅会同步移出当前源管理列表，保留个人收藏与观看记录。搜索按片名相关性排序并过滤上游夹带的无关条目。网页封面由浏览器直接获取，在“设置 → 封面设置”选择 LunaTV 使用的腾讯云 CDN、阿里云 CDN 或自定义图片源，默认腾讯云，按账号保存并跨设备同步。加载失败时自动重试并切换 CDN，再尝试同作品备用封面；全部失败后显示片名占位。

管理员导入订阅时可选择“所有用户／指定用户／仅管理员”，已有订阅通过“使用用户”修改范围。“仅管理员”无需选择成员，所有普通成员均不可用；订阅刷新保留范围，管理员始终可用。网页和飞牛共用使用范围，撤权后保留个人记录并标记无权限，停止本站转发，重新授权后恢复可用。回归范围见 [账号图片设置与订阅授权验收](docs/verification-user-settings-20261119.md) 和 [此前订阅、封面与搜索回归](docs/verification-20261119.md)。

管理员可在“设置 → 家庭账号”停用或删除其他成员。删除前显示确认提示，确认后立即撤销登录会话，清理该账号的收藏、观看进度、播放日志、偏好和来源授权，并停止其正在转发的播放；删除不可恢复。当前管理员不能删除自己，其他成员的数据独立保留。

## Docker 部署

默认使用 GitHub Actions 构建并发布的 `ghcr.io/lengyuesky/tv-rust:latest` 镜像。如需固定版本，修改 `compose.yaml` 中的 `image` 标签。

```sh
cp .env.example .env
docker compose pull
docker compose up -d
```

打开 `http://服务器地址:3000`，设置管理员，再到“设置 → 订阅与视频源”导入配置。其他家庭成员在“家庭账号”中创建。

`.env` 中的设置：

| 变量                        | 用途                                                                                        |
| --------------------------- | ------------------------------------------------------------------------------------------- |
| `TV_PORT`                   | 对外端口，默认 `3000`                                                                       |
| `TV_PUBLIC_URL`             | 其他设备或反向代理使用的完整服务根地址，例如 `https://tv.example.com`；留空使用当前访问地址 |
| `TV_ALLOW_PRIVATE_UPSTREAM` | 连接局域网订阅或视频源时设为 `1`；默认 `0`                                                  |

单容器包含 Rust、网页与媒体元数据探测工具，使用 SQLite 命名卷 `tv-data` 持久化。容器以普通用户运行，临时探测使用 `/tmp`。支持 `linux/amd64` 和 `linux/arm64` 构建：

```sh
docker buildx build --platform linux/amd64 --load -t tv-rust:amd64 .
docker buildx build --platform linux/arm64 --load -t tv-rust:arm64 .
```

本地构建后，将 `compose.yaml` 中的 `image` 改为对应的本地镜像标签，再执行 `docker compose up -d`。当前本机运行情况和实际播放范围见 [验收记录](docs/verification-20261112.md)。

## GitHub Actions 镜像发布

[检查与镜像发布工作流](.github/workflows/check.yml) 先运行格式、Clippy、Rust 测试和网页构建，再让 AMD64 与 ARM64 各使用一台原生 Ubuntu runner 并行构建。公开仓库的 `ubuntu-24.04` 和 `ubuntu-24.04-arm` 均为 [4 核、16 GB 内存的免费标准 runner](https://docs.github.com/en/actions/reference/runners/github-hosted-runners#standard-github-hosted-runners-for-public-repositories)，并行构建阶段合计可用 8 核、32 GB。Rust 使用每台 runner 的全部可用 CPU，依赖单独分层并按架构保存构建缓存，保留 release 优化。

检查使用 runner 现有编译工具，固定并缓存通过 AMD64 受控素材验证的 FFprobe 测试工具，避免重复运行 Ubuntu 系统包安装。网页只构建一次，再将同一产物交给两种架构。每个架构只执行一次 Docker 构建，同时导出本地镜像和 GHCR 摘要；本地镜像通过普通用户、只读文件系统下的空启动、健康接口、网页和 FFprobe 检查后，才合并清单并更新发布标签。缓存上传失败不阻断镜像发布。普通本地 `docker build` 仍可直接从源码构建完整镜像。

工作流使用 `GITHUB_TOKEN` 授权 GHCR。构建故障原因和本轮验证见 [构建优化记录](docs/build-20261119.md)。

| 触发方式                          | 发布标签                             |
| --------------------------------- | ------------------------------------ |
| 推送 `main` 或在 `main` 手动运行  | `latest`、`sha-<完整提交 SHA>`       |
| 推送版本标签，如 `v0.1.0`         | `0.1.0`、`0.1`、`sha-<完整提交 SHA>` |
| Pull Request 或在其他分支手动运行 | 检查与原生构建                       |

版本标签必须与 Rust 和网页的版本一致。公开镜像地址为 `ghcr.io/lengyuesky/tv-rust`，Docker 会按主机架构选择 AMD64 或 ARM64。

## 飞牛连接和播放

在飞牛播放器中添加同一个服务根地址，使用网页账号登录。首页的电影、剧集目录来自当前账号的收藏与观看记录；原生搜索查询当前账号获准使用且已启用的视频源。此前本机飞牛播放器 `1.12.3 / 1123003` 已验证受控 MP4、普通 HLS、AES-128 HLS 及播放中换源，范围见 [飞牛 HLS 交付与画质验收](docs/verification-fntv-delivery-20261122.md)。本次使用 `1.13.0 / 1130013` 验证禁止转发下的普通 HLS 直链及客户端方式显示，见 [禁止转发与客户端显示验收](docs/verification-fntv-no-proxy-20261122.md)。

网页默认向客户端交付媒体直链，只在明确的网络或跨域错误时自动回退一次，也提供“转发重试”。确认为播放器网页的地址会提示需要额外解析，可以换源。

飞牛 MP4 使用 STRM 直链协商，单源附带独立 URL 片段关联播放；片段不随 HTTP 请求发送给视频源。多源通过本站短期菜单选择媒体，空认证头的 MP4 请求跳转至原地址，携带本站认证头的请求使用同源转发。HLS 在允许转发时沿用原生同源清单通道，保留 `.m3u8` 后缀并交付完整清单；开启“禁止转发”后改用 STRM 直链通道和空媒体请求头。本站读取、解压并整理清单，客户端直接读取上游视频、音频、密钥和初始化分片。本站登录头不发送给媒体源。

上游 HTTP 清单支持 gzip、Brotli、deflate 和 Zstandard 解压，旧的未识别 HLS 文件缓存重新探测。图片扩展名下的 PNG 图片头／MPEG-TS 分片使用 `.ts` 短期重定向和标准 HLS 字节区间，客户端从图片头之后直接读取视频。首次识别每个分片最多读取 4 KiB，结果缓存一小时；不能确认视频或不支持区间的来源提示换源，保持禁止转发。真实片源与账号删除验证见 [实源压缩清单、图片头分片与账号删除验收](docs/verification-fntv-live-20261122.md)。

分片识别在整个服务中最多并行 32 个请求，复用已验证且 DNS 结果相同的上游连接；短暂连接失败和临时 HTTP 错误最多重试一次。缓存按批读取并集中提交，失败后保留已完成的区间识别结果。清单失败会写入“播放日志 → 查看过程”，区分清单读取与分片区间识别；服务日志保留脱去地址后的网络错误，便于核对部署环境中的实际连接问题。

禁止转发时，飞牛起播前会检查当前 HLS 的清单、加密方式、首分片及必要的视频区间。每条来源的准备限三秒；失败后，在八秒内从账号获准使用、能确认同一作品和同一集的来源中寻找可直连的替代：先按画质顺序确认已识别出真实视频的来源，再现场识别尚未识别过的来源。来源发现最多占用其中四秒，识别结果过期的 HLS 来源仍可作为候选。替代来源重新检查清单与首分片，返回它自己的媒体身份；本次自动换源起播优先使用原、目标来源该集更新时间更晚的进度，同秒仍用目标自己的。原来源记录必须属于换源前的那一集，沿用时回退 5 秒且不小于零；目标时长已知且原位置已到片尾前 30 秒或之后时不沿用。准备过程不复制或写入观看进度，日志记录原来源失败的原因、实际选择及沿用的起播位置。没有确认可用的来源时保留失败，不开启转发。验证范围见 [禁止转发下的起播准备验收](docs/verification-fntv-direct-start-20261123.md)。

采集源的“云播”线路返回网页播放器或分享页，不是媒体文件。服务端探测确认是网页的地址、以及没有识别出视频且地址不是媒体文件形态的线路，不会作为直链交付，也不进入飞牛来源菜单；没有观看记录时默认线路优先选择能直接交付媒体的线路。已知加密的 HLS 在禁止转发时排在菜单最后。来源画质识别独立于发起它的请求，在后台完成并保存：起播最多等待一秒半，详情页最多等待三秒，未识别完的来源沿用同一地址上一次的结论。

健康接口 `/api/health` 和账号接口 `/api/me` 返回 `build_revision`，发布镜像中为实际构建的 Git 提交。可据此确认公网运行的是哪次修复；未传入构建修订的本地构建显示 `development`。

飞牛的 AES-128 HLS 转发按分片解密，保留视频编码、分辨率和帧率，不转码或缓存整部影片。该能力服从全局“禁止转发”设置；当前支持完整分片的 AES-128，SAMPLE-AES、DRM 和加密字节区间会明确提示换源。客户端请求“NAS 代理播放”入口时会为本次会话直接建立转发，也可继续在网页“播放日志”准备单次飞牛重试。详情显示实际探测的分辨率、编码和帧率，未知信息显示“画质待识别”。探测确认媒体返回 404／410 时明确提示地址已失效；刷新或换源不会修改个人收藏和其他来源的进度。

管理员可在“播放设置”开启全局“禁止转发”。该设置覆盖自动回退、手动重试、飞牛请求和已签发的转发地址，开启时停止现有转发。客户端已缓冲的画面可能短暂继续。

客户端“文件信息”的“文件位置”显示直链或转发，起播后的媒体名称和视频信息也包含所选方式；尚未起播时标明“待播放”。这些字段描述交付方式，不代表已成功解码。普通 HLS 已验证可在禁止转发时出画；受控 AES-128 样本在本机 `1.13.0` 的 STRM 直连下仍报 `-99985`，需要换用客户端能直接播放的来源，或允许必要的解密转发。禁止转发不会自动开启解密转发。

探测会排除封面流，并在 PNG 图片头后确认 MPEG-TS 数据时识别真实视频编码和尺寸；旧的 PNG 探测缓存会重新识别。地址或分片确实返回图片时提示刷新来源或换源，不将小图片标记为视频画质。媒体探测结果通常缓存 6 小时；上游明确拒绝（HTTP 400–499，不含 408／429）及已确认的网页、图片缓存 24 小时，减少无效重复探测。主动“刷新来源”仍会立即重新探测。

播放日志区分地址交付、播放器事件、进度回传与资源转发，记录方式变化及原因；普通用户只能看自己的日志，管理员可看全部，默认保留 30 天。地址交付、非零进度或收到转发字节都不能单独证明客户端实际解码成功。

## 换源与观看状态

播放页在视频下方直接列出可切换的播放源名称和对应单集的探测分辨率，按画质从高到低排列，当前源高亮。点击其他来源时优先使用已识别的较高画质线路；未知画质或无法确认集号的来源排在最后，不把上游“4K／蓝光”等文字当成真实画质。打开页面先显示已保存的候选，再自动补齐来源和画质，“刷新来源”会重新查询和探测。候选需当前账号获准使用，且标题、明确年份、类别和版本一致；某个源暂未响应时，其余结果仍可使用。

播放线路统一放在视频下方的切换区域；`liangzi`、`lzm3u8` 等内部标识显示为“线路 1、线路 2”，中文线路名称保留。切换线路后选集区域显示该线路的集数，不再重复显示线路标签。

正在播放时按实际集号匹配目标单集，能确认时保存最终进度并自动开始新播放；合辑或重复集号等无法确认的情况先让用户选集，原播放在确认前继续。切换同一影片的线路承接当前播放位置，跨来源使用各自的观看进度，不自动复制旧来源的位置或收藏。也可继续使用详情中的“搜索其他源”入口。

播放器上方显示具体画质，例如 `720p · 1280 × 720 · H.264 · 24 fps`。播放前使用真实媒体探测信息，播放后以浏览器实际解码尺寸为准，多档 HLS 的编码及帧率跟随对应档位；未知信息显示“画质待识别”。桌面及手机均支持显示，回归范围见 [播放页换源与画质验收](docs/verification-playback-20261120.md) 和 [线路与来源画质排序验收](docs/verification-source-quality-20261120.md)。

进度保存按账号和来源条目隔离。网页关闭、切集、换源和退出登录会先保存最终快照，快照和会话结束在同一数据库事务中完成；旧会话的迟到回传不能覆盖新会话。

网页首页“继续观看”、网页“最近观看”和飞牛“继续观看”都将同一作品的多个来源合并为一张卡片，使用最近观看的来源、单集和进度；同一秒内换源按播放会话先后选择。首页展示最近六部，网页最近观看和飞牛列表分别最多展示 1000 部和 100 部。不同年份、类别、版本或无法确认年份的作品分别显示；底层各来源的独立进度仍保留。

允许转发的 HLS 原生播放通道已实测支持播放器底部的画质／来源按钮。当前 `1.13.0` 的 STRM 直链界面可能不显示该按钮，因此禁止转发时在起播前准备并选择可用来源。菜单标签只显示源名称，同一来源有多条线路时追加线路编号，例如 `红牛资源/2`；普通菜单按真实探测画质从高到低排列，未知画质排在最后；画质相同时，近 7 天识别出过真实视频的视频源优先，全部被上游拒绝的视频源后置，其余居中。HLS 直链将本次实际选择的来源固定在首项，其他来源沿用画质顺序，避免 STRM 默认读取首项时改变来源。来源只包含当前账号获准使用且可以确认同作品、同集的媒体；实际集号按“第03集／第三集”等标题识别。普通跨来源起播仍使用各自的进度，仅上述禁止转发下的自动换源承接较新的同集位置；飞牛播放中显式换源的位置由客户端控制，实际回传分别写入选中的来源。旧播放的退出通知和迟到进度不会结束或覆盖新的来源。

飞牛“我的剧集”“我的电影”、收藏、搜索和继续观看都按同一作品显示一条；作品、季和可确认的单集使用稳定身份。剧集详情只列一季和统一的单集目录，合并其他来源可确认的缺集，简介只展示作品内容。来源选择统一放在播放菜单中，详情仅展示当前媒体。实现参考 [fnmedia-ext](https://github.com/funwukong/fnmedia-ext) 的原生清晰度菜单协议，本机验证见 [飞牛播放中换源验收](docs/verification-fntv-player-menu-20261121.md)。

网页“最近观看”可移除记录；飞牛长按“继续观看”卡片，选择“从继续观看中移除”。删除会清除当前账号在该作品所有来源的观看进度，保留收藏；旧播放会话的迟到上报和结束快照不能恢复记录，正在播放的媒体仍可继续。主动重新播放才开始保存新记录。实际客户端及浏览器验证见 [飞牛换源、画质与观看记录验收](docs/verification-fntv-history-20261121.md)。

## 升级、备份和恢复

升级或重建继续使用命名卷：

```sh
docker compose pull
docker compose up -d
```

可在网页“设置 → 飞牛与数据”下载一致性数据库备份，也可以在运行中执行：

```sh
mkdir -p backups
docker compose exec tv-rust tv-rust backup /data/manual-backup.sqlite
docker compose cp tv-rust:/data/manual-backup.sqlite ./backups/manual-backup.sqlite
```

备份路径必须是新文件。当前账号、订阅、目录、个人数据及日志都存储在 `tv.sqlite`；临时媒体探测文件无需备份。运行中的 SQLite 数据库应通过上述备份入口导出，以包含 WAL 中已提交的数据。

恢复会用备份替换当前数据库，先保留一份当前备份，再停止服务并导入：

```sh
docker compose stop
docker compose run --rm --no-deps --user root \
  --entrypoint /bin/sh \
  -v "$PWD/backups/manual-backup.sqlite:/backup.sqlite:ro" \
  tv-rust -c 'rm -f /data/tv.sqlite-wal /data/tv.sqlite-shm; cp /backup.sqlite /data/tv.sqlite; chown 10001:10001 /data/tv.sqlite'
docker compose up -d
```

忘记管理员密码时，可在本机运行恢复命令，新密码从标准输入读取：

```sh
docker compose exec tv-rust tv-rust reset-password 管理员用户名
```

修改密码会撤销该账号全部设备的旧登录和播放授权，需要重新登录。

## 本地开发与重复验收

需要 Rust stable、Node.js 22 或更新版本，以及 `ffprobe`。默认服务地址为 `0.0.0.0:3000`，数据目录为 `data/`，网页目录为 `web/dist/`：

```sh
cd web
npm ci
npm run build
cd ..
cargo run --locked
```

检查命令：

```sh
cargo fmt --check
cargo clippy --locked --all-targets -- -D warnings
cargo test --locked
npm --prefix web test
npm --prefix web run build
```

生成和运行受控 MP4/HLS 素材：

```sh
node tests/fixtures/media.mjs
FIXTURE_BIND=0.0.0.0 FIXTURE_PUBLIC_URL=http://本机局域网地址:55321 node tests/fixtures/server.mjs
```

对独立空数据库运行 API 验收，服务应允许访问受控的局域网视频源：

```sh
TV_TEST_URL=http://127.0.0.1:55320 \
TV_TEST_FIXTURE=http://本机局域网地址:55321/config.json \
node tests/acceptance.mjs prepare
node tests/acceptance.mjs snapshot
node tests/acceptance.mjs check
node tests/acceptance.mjs backup
```

`prepare` 只允许未初始化的数据库；输出写入 `tmp/continuation-20261112`，可通过 `TV_TEST_OUTPUT` 指定独立目录。API 验收不替代浏览器或飞牛的实际画面观察。

验收账号密码每次 `prepare` 随机生成，保存在该输出目录的权限 `600` 会话文件中。后续 `snapshot`、`check`、`backup` 和 `native-session` 使用同一会话文件。需要指定密码时可设置 `TV_TEST_PASSWORD` 与 `TV_TEST_MEMBER_PASSWORD`。

需求和设计决策见 [设计记录](docs/design.md)、[调查记录](docs/research-20261112.md)、[术语表](GLOSSARY.md) 与 `docs/adr/`。
