## 点播接口与播放限制

抽样包含分类、分页、关键词搜索、ID 详情，共 7 次元数据 GET，其中 6 次返回 JSON、1 次 TLS 连接失败。未请求影片播放地址、HLS 清单或分片。

- 接口采用苹果 CMS 风格，实测有 `ac=list`、`ac=videolist`、`ac=detail`，以及 `wd`、`ids`、`t`、`pg` 参数。
- API 的原有路径必须保留，不能假设所有源都使用 `/api.php/provide/vod`。部分配置已有代理包装查询参数。
- 同一分类 ID 在不同源中含义不同；页码和数量可能混用字符串与数字。
- 成功响应存在 Content-Type 为 `text/html`、正文却是 JSON 的情况。
- 详情中的 `vod_play_url` 包含集名与 URL，已观察 `$` 分隔集名、`#` 分隔单集及多余的尾随 `#`。上游 LunaTV 还按 `$$$` 分隔播放线路。
- 爱奇艺源样本包含使用非标准 HTTPS 端口的 `.m3u8` URL；金鹰源包含 `/play/...` 样式 URL，因未请求资源，不能确定其 MIME 或是否能提取媒体。
- 视频源能返回搜索 JSON，不证明它当前可播放。上游健康检查同样不构成播放验证。

元数据响应与公开仓库快照在调查时保存在 `临时调查目录`；这是临时复核材料，不是项目运行依赖。

- 首页热门电影、剧集和综艺使用豆瓣数据，番剧日历使用 Bangumi；点播配置本身不含推荐榜单。
- 聚合搜索、详情选集、播放、切源、收藏与历史是独立功能。
- 上游收藏和进度按用户隔离，使用源 ID 与源内影片 ID 关联。跨源匹配主要依赖标题、年份与类型，集数位置不保证内容一致。

- 查阅的主仓没有 Emby 服务端兼容的实现证据；其客户端推荐不能用于推导飞牛协议兼容性。

## 本机飞牛与工具环境

- `/Applications/Runner 2.app/Wrapper/Runner.app/Info.plist` 显示飞牛播放器 1.12.3、构建 1123003、bundle ID `com.trim.media.ios`，为可在本机运行的 iPhoneOS 客户端。
- 相邻项目 `tgdrive/src/apps/fntv/` 提供 Fn 兼容服务端，以 `/trimcon`、`/v/api/v1/sys/version`、`/v/api/v2/user/loginByPassword` 等接口服务飞牛客户端；没有经由 Emby，也不读取真实 fnOS 媒体库。
- 现有代码涵盖电影、剧、季、集、播放与进度；其播放响应固定 `is_m3u8: false`，数据来自文件直传和 HTTP Range。它不能证明 LunaTV 远程 HLS 在飞牛中可播放。
- 现有参考使用单一影视账号，进度与收藏没有用户维度。本项目已确定的家庭多账号需要独立设计。
- Docker CLI 29.8.2、Compose v5.5.0、OrbStack 2.2.5 已安装；调查时 Docker socket 不存在，服务不可连接。
- Rust stable 1.99.0 已安装，但当前 PATH 不含 `~/.cargo/bin`；可通过完整路径调用 rustup。
- Node 26.10.0、npm 11.19.1、pnpm 11.25.0、uv 0.12.21 可运行。

飞牛的握手登录、媒体目录、HLS 播放、拖动、续播、多账号隔离均需以本项目实际实现和本机客户端测试为准。

## 直链优先的补充核验

用户将播放策略改为直链优先后，补充只读检查了当前协议实现和公开验收记录。

- `POST /v/api/v1/play/info` 当前返回媒体、轨道、续播位置等信息，不直接交付 URL。
- `POST /v/api/v1/stream` 中的 `file_stream.path` 是原网盘路径，`direct_link_qualities` 为空，`is_m3u8` 为假；这些字段不能作为外部直链已经验证的证据。
- `POST /v/api/v1/play/play` 返回随机关联标识 `play_link`，既有记录指出本机对应版本未调用该接口，不能将该标识当成 URL。
- 当前已观察的原生取流入口是 `GET /v/api/v1/media/range/{media_guid}`，验证的是由宿主返回文件的路径。
- `/play/record` 已观察到进度回传，`/play/quit` 已观察到退出回传；现有代码与记录未证明存在包含直接播放失败原因、HTTP 错误或要求转发信号的原生回报。
- 单次非零位置可以来自续播定位或拖动，连续推进是更强的进度证据，但不能代替观察画面与声音。返回 200/206 或已经开始转发字节也不能独立证明客户端成功解码。
- 现有进度绑定由宿主媒体 GET 激活，外部直链可能绕过该路径。因此新项目的播放身份与进度绑定不能原封不动复制现有基于媒体读取的判定。
- 当前统计仅供测试使用，已有请求审计属于测试夹具；本项目的产品播放日志需要独立实现。

关键源码参照：`tgdrive/src/apps/fntv/protocol.rs` 第 743、793、802、825、835、861 行；`tgdrive/src/apps/fntv/mod.rs` 第 350、358 行。

当前可确定的设计约束是将“选择并交付的播放方式”与“服务端实际观察到的状态”分开记录；外部直链、HLS、必要回退及直链情况下的进度保存需联合进行本机验证。
