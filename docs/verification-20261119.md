# 订阅移除、浏览器封面与搜索回归

日期：2026-11-19（Asia/Shanghai）。本轮针对设置页重复追加“（已移除）”、首页封面失败和搜索结果中无关 NBA 条目排在首位的问题。

## 已确认的修改范围

- 订阅移除后从当前订阅与源管理列表隐藏，数量同步变化；重复移除保持相同结果，保留收藏、历史、进度和来源身份。重新导入创建新订阅。
- 全部网页封面由浏览器直接获取。失败时每个地址自动重试一次；有可靠的同作品候选时切换备用地址，否则显示片名占位和手动重试。推荐列表重试保持电影或剧集分类。
- 搜索按片名匹配，完全匹配、包含完整词、多个词全部匹配依次排序；不按体育类型设置黑名单。无关条目在入库前过滤，切换关键词时旧请求不能覆盖新结果，已加载分页合并去重并重新排序。

## 实现与数据兼容

新增 `subscriptions.removed_at` 和数据库版本迁移。移除状态、订阅更新地址清空与来源失效在同一事务内执行，共用配置刷新锁，避免失败时只完成一半或刷新重新启用来源。当前管理列表只列出未移除订阅内仍存在的源，禁用选择继续保留。

旧版记录仅在“地址已清空、名称带移除后缀、存在所属来源且这些来源全部失效”同时成立时迁移。迁移去掉重复后缀、隐藏记录，继续保留关联数据。单凭空地址或名称不判断移除，正常文本订阅继续显示。

网页直接使用封面原始 URL；相对地址按视频源地址补全，封装在 `?url=` 内的上游地址也参与解析。重试通过重新挂载图片实现，保持原始地址及查询签名。新的候选接口只返回 URL，未转发图片字节。普通片源候选必须有一致片名、明确年份、类别和版本；推荐候选先按豆瓣 ID补充年份和类别，且只从本地已保存、当前启用的来源中取图，不为封面发起全源搜索。

## 公开上游调查与边界

用户截图中的公开订阅可定位到“🎬最大资源”。2026-11-19 抽样时，`ac=videolist` 对“你好”和一个明确无关词返回相同 20 条影片 ID，`ac=detail` 也相同，包含 5 条 NBA 赛事；没有任何片名匹配“你好”。`ac=list` 对“你好”也未取得匹配，且缺少年份、图片和播放字段，因此未增加没有检索收益的接口回退。本地筛选能去掉这些内容，不能凭空补出上游未返回的相关候选；源状态会显示过滤数量。

网页后续页仍依据上游 `pagecount` 查询，服从 500 页上限；某一页没有片名匹配不能证明后续页均无匹配。飞牛本轮同步筛选与相关性顺序，其上游与客户端分页的完整映射未在本轮重新设计或进行原生验收。

豆瓣推荐 API 抽样可返回电影与剧集列表，但图片样本无 Referer 返回 418、应用 Referer 返回 403，仅固定豆瓣 Referer 返回有效 JPEG。本机 Chrome 157 对同一公开图片直接加载也观察到 418、`naturalWidth=0`，证据为首轮目录中的 `public-browser-cover.json`。浏览器无法任意设置外域 Referer。为遵循用户确认的浏览器直取要求，本轮保留明确占位与可靠候选兜底；没有候选且原站拒绝直取时，封面仍可能无法显示。

本轮使用独立数据库和受控图片，没有更新用户实际部署、访问其真实数据库，或重新进行飞牛原生播放验收。飞牛相关性修复的证据来自接口集成测试。
