## 实现补齐

- HLS 播放库按需加载；播放器保存进度串行执行。关闭、下一集、直接选集、换源导航和退出登录等待保存，最终快照与会话结束在同一 SQLite 写事务中提交。页面关闭使用包含快照的 keepalive 请求。同步失败显示提示并保留播放器供重试。
- 搜索选源传递 `switch_from`；详情返回当前账号的 `switch_hint`。匹配依据标题、已知年份、版本与实际集号，不使用来源中的排序位置猜测集号。合辑、特别篇、明显不同版本或重复集号要求重新选集；换源不复制进度或收藏。
- 修复恢复前已有的 SQLite 并发写锁问题，并继续保留最新播放会话优先及旧播放标识拦截。
- 本机飞牛实测发现 STRM 把交付的媒体 URL 用作 `play_link`。重复交付相同 URL 会与旧会话冲突，导致新回传被拒绝。当前补丁为每次直链附加独立 URL 片段，并提前绑定标识；片段不发送给上游 HTTP 服务。长签名 URL 和旧回传拦截已通过回归与容器协议检查；本轮原生客户端实际完整保留并回传该片段，新会话进度能够保存。
- Docker 构建增加目标架构校验，网页阶段使用构建主机架构；服务支持 SIGTERM 正常退出。增加运行、备份、恢复和密码恢复说明。
- 飞牛准备手动转发后，迟到的直链进度不清除等待重试状态；交付转发地址后才结束等待，旧直链回传不能覆盖转发会话。

### 本轮媒体修复

- 长 HLS 清单的资源映射预先汇集，使用 `BEGIN IMMEDIATE` 单事务与批量插入，已登记项不重复写入。12000 项资源限制在事务内检查，超额不留下部分映射。真实 2452 分片清单从约 33 秒降至约 1.7 秒交付（网络耗时会波动），避免逐分片写入造成的 SQLite 锁竞争。
- 转发路径保留安全媒体后缀，密钥统一使用 `.key`，兼容 FFmpeg 对分片扩展名的检查。媒体清单请求移除 Range/If-Range，重写后返回完整 200；分片继续支持 Range。
- AES-128 HLS 使用限 16 字节密钥和限 512KiB 首分片进行本地元数据探测，远端请求均经过统一网络校验。FFprobe 仅允许本地 `file,crypto` 协议和指定扩展名；不向 FFprobe 传远程清单。旧版空音轨缓存会重新探测一次。光速影片已探测出 H.264 1280×506、AAC 双声道和约 8188 秒时长。
- 新增约 8.5KB 的合成加密 HLS 回归素材，生成方式和公开测试密钥见 `tests/fixtures/hls-probe/README.md`。这些修复和服务端探测成功均不能替代飞牛实际解码验收。
