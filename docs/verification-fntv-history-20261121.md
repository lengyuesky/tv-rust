# 飞牛换源、真实画质与观看记录验收

日期：2026-11-20 至 2026-11-21（Asia/Shanghai）。本轮用户要求同时修复飞牛和网页重复的观看记录、飞牛换源及来源画质，以及无法删除记录的问题。

## 最终行为

- 网页首页、网页最近观看、飞牛继续观看都按同一作品去重，选择当前账号最近的来源、实际单集及进度。首页最多六部，网页记录最多 1000 部，飞牛最多 100 部，先去重后限制数量。不同年份、类别、版本或无法确认年份仍分开。
- 删除唯一卡片，清除该账号在同一作品所有来源的进度，保留收藏和其他账号的数据。清除记录与禁用旧会话的进度写入在同一事务提交；旧上报、关闭快照及已切换来源的旧会话不能恢复或覆盖记录。媒体可继续，重新主动播放的新会话正常记录。
- 飞牛原生剧集来源卡片显示源名称、线路、参考集号、实测分辨率和尺寸，按画质排序；点击后可从目标来源的同一集继续。原生电影及单集的版本按钮也按画质排序，选中后文件位置和视频信息显示对应源、尺寸、编码和帧率。技术线路名显示为中文“线路 1／2”，季号保留第 1 季，集号从实际标题识别。
- 候选只包含授权且可确认同作品同集的来源和线路，合辑、重复集号、不同年份等不自动匹配；不采用上游“4K／蓝光”宣传字样或其他集数的探测值。未知画质标为待识别。8 秒发现与识别预算、六小时缓存及后台一个媒体探测槽限制慢源开销，来源查询不创建观看会话。
- 原生版本标识写入数据库，清缓存或重启不会丢失；失效的参考单集明确失败。原生季卡片固定显示“第 1 季”，因此使用内置 Noto 中文字体渲染来源信息 PNG，使源名称和画质可见。图片请求检查账号和实际媒体权限，不改变网页封面来源；字体许可随源码及镜像提供。
- STRM 仍直接交付原媒体地址，空请求头和每次播放的独立 URL 片段保留。跨来源读取目标独立进度，同来源换线路匹配同集进度，协商成功后结束本次登录下的旧来源会话。

## 本机飞牛实际验证

使用 Mac 中已安装的飞牛播放器 **1.12.3 / 1123003**（iPhoneOS 兼容运行时），连接独立本地测试数据库及受控媒体，没有使用用户生产数据库或实际部署。

- 三个来源的同一剧集在原生“继续观看”只显示一张，实际第三集显示“第 3 集”，即使原来源第三集是目录中的第二项。
- 原生剧集详情实际显示四张来源版本卡片：源 C 的 1080p、源 B 线路 2 的 720p、源 B 线路 1 的 360p、源 A 的 360p，卡片源名称、集号、尺寸、编码及帧率清晰可见。
- 点击源 B 的 720p 卡片，进入该源线路 2，原生页面显示完整源名称、画质、三集目录及“第 3 集”播放按钮。播放后实际出现受控测试画面，从该来源自己的 13 秒开始；其随后真实回传更新到 228 秒，源 A 的 2 秒及源 C 的 12 秒未被复制或改写。
- 原生单集详情实际出现 `1080P、720P` 版本按钮；选中 1080P 后文件位置显示源 C、`1920 × 1080` 和 H.264，视频信息显示 `1080p H264 7.54 mbps`。播放从源 C 的 12 秒开始，观察并保存了真实画面。
- 受控服务器收到 14 次 `trim_player` 原生媒体读取，路径对应实际选择的 720p／1080p 文件，全部无 Cookie 和 Authorization。Rust 服务仅负责探测与协商，未为这些原生观看转发视频。
- 换源后原生继续观看仍只有一张。长按并选择“从继续观看中移除”，客户端实际显示“移除成功”，卡片消失；数据库确认所有三源进度数量为 0，旧会话均标为禁用记录。

原生证据主要为 `tmp/fntv-native-20261120-iItx0q/`，包含来源卡片、720p 和 1080p 单集选择截图、实际解码画面、原生脱敏请求、媒体请求和删除后的验证 JSON。初次删除的界面截图在 `tmp/fntv-native-20261120-vlsBWL/history-removed.png`。最终持久化版本标识及失效参考单集另由自动测试覆盖。临时浏览器、媒体夹具和服务均已停止。

本轮原生实际播放覆盖受控 MP4；没有宣称用户截图中的全部外部源或各类 HLS 均已通过，也未改变此前所测 AES-128 HLS 的原生兼容性结论。升级镜像需要由用户实际部署执行。
