## 当前事实

- 当前工作目录为 `tv-rust`，开始工作时为空，没有既有代码、部署文件或项目术语表。
- 指定配置仓库的 `main` 在调查时为 `d71f1c57fa0e3f598b6251a102780c68f64ba5ea`。实际配置以 `cache_time` 和 `api_site` 为顶层字段；JSON 与 Base58 文本表达同类配置，不包含飞牛服务端接口。
- 调查时完整版含 69 个源、精简版含 47 个源、`jin18` 版含 28 个源。README 的源数量与实际文件不一致，兼容实现应以文件内容为准。
- `jin18` 版去除名称标为成人的源，但普通源的分类中仍可能有明确成人类别；源筛选与分类过滤是不同能力。
- 采样源的播放结果有 `.m3u8` 地址，也有 `/play/...` 这类播放器样式地址；调查没有请求播放资源，其实际响应类型和可播放性尚未确认。配置可导入与内容可直接播放不能等同。
- 本机安装的是 `/Applications/Runner 2.app` 中的飞牛播放器 1.12.3（构建 1123003），属于可在 Mac 运行的 iPhoneOS 客户端。
- 相邻 tgdrive 项目的现有代码采用“飞牛客户端连接模拟飞牛服务端”的方式，不能据此宣称新项目已经验证飞牛播放远程 HLS。
- Docker CLI 29.8.2 与 Compose v5.5.0 已安装，但调查时 OrbStack Docker socket 不存在，Docker 服务尚不可连接。Rust stable 1.99.0 已安装，可通过 `~/.cargo/bin/rustup run stable` 调用。
- MoonTV 当前继承项目的首页热门榜单依赖豆瓣，番剧日历依赖 Bangumi；这些内容并未包含在视频源配置中。
- 相邻项目的飞牛 `POST /v/api/v1/item/list` 实现解析 `q`、`ancestor_guid`、`page`、`page_size` 与 `tags.type`，可作为搜索与分页适配的接口参照；现有文档和测试尚不足以证明原生客户端实际发出了非空搜索词。
- 调查出处与兼容限制见 [2026-11-12 事实调查](research-20261112.md)。

## 第一轮：可独立决定的产品边界

### Q1：Rust 的范围

已确认：服务端使用 Rust，承担配置解析、搜索聚合、数据存储、媒体代理及飞牛连接接口；网页界面使用 React/TypeScript。

### Q2：首版网页功能

已确认：以电影、电视剧点播为主，覆盖聚合搜索、详情与选集、在线播放、切换视频源、收藏、播放历史与续播、配置管理，并完成飞牛影视接入。

### Q3：使用人群与个人数据

已确认：面向个人和家庭使用，每位使用者有独立账户、收藏和播放进度，由管理员统一管理视频源。

## 第二轮：配置与连接边界

### Q4：飞牛连接方向

已确认：在已安装的飞牛播放器中添加本项目的服务器地址，使用本项目账号，浏览并播放本项目提供的点播内容。本项目提供飞牛兼容服务端接口。

关键待验：现有相邻项目验证的是文件直传；本项目需优先实测飞牛播放器播放远程 HLS 的能力。

### Q5：配置订阅及更新

已确认：管理员可导入 JSON、Base58 配置文本或订阅 URL；支持手动更新和定时刷新，遵循有效的 `cache_time`，没有有效值时默认两小时；更新失败保留最近一次有效配置，保留管理员按源启停的选择。

### Q6：初始配置

已确认（用户修正）：不预置视频源、配置内容或订阅地址，由管理员自行导入。首次启动显示空源状态和导入入口。撤回原先默认使用 `jin18` 及默认成人分类过滤的建议。Q5 中已经确认的 JSON、Base58 文本与订阅 URL 导入能力继续适用。

用户原话：“q6，不默认配置源，只需要支持源订阅导入就行，其他确认”。

### Q7：首版播放兼容范围

已确认：完整识别订阅中的源配置，首版播放支持经探测可识别的 MP4/HLS 地址，包括带查询参数或无标准后缀的地址；确认为网页且需要额外解析的条目明确提示，并允许用户换源。

### Q8：默认访问范围

已确认：Docker 部署面向家庭内网，所有用户登录后使用；保留配置外部访问地址的能力，便于用户后续通过域名与 HTTPS 反向代理访问。

### Q9：首页推荐

已确认：首页加入豆瓣热门电影与剧集推荐，点击推荐条目后搜索视频源；同时提供个人继续观看和收藏入口。推荐服务不可用时展示本地入口和明确状态，搜索与播放继续可用。

## 第三轮：媒体库、观看状态与部署

### Q10：飞牛媒体库与搜索

已确认：飞牛首页提供个人收藏与看过的内容；用户可直接在飞牛内搜索全部已启用的视频源，找到影片后选集播放。个人收藏与最近观看形成持续可浏览的媒体目录，避免依赖提前收集所有源的完整目录。

实现与验收需明确：服务端存在可映射搜索词的接口，不等于本机客户端已经验证了此行为；原生搜索需在本项目中实测，不能以网页搜索替代该项验收。

### Q11：跨源条目与跨端进度

已确认：网页和飞牛共享同一用户的收藏与观看进度。搜索时可将标题、年份一致的候选聚合展示，但保留各个源条目；同名不同年份或明显不同版本分别呈现。切换源时尝试对应集号，不确定时由用户重新选集，避免把合辑、删减版或特殊篇误当成相同单集。

具体存储身份将依赖 Q12 的订阅归属选择；展示聚合不自动合并来源记录。

### Q12：多个订阅与失效源

已确认：支持多份订阅并存，同名源 ID 分别归属各自订阅；管理员可以禁用重复源。源从订阅中移除或被禁用后，不再参与新搜索和新播放，原有收藏与历史继续保留，展示来源失效状态，并允许用户重新选择其他源。

### Q13：播放链路

已确认（用户修正）：优先向网页与飞牛客户端提供可直接获取媒体的地址；仅在必要时使用 Rust 服务转发。播放日志必须明确展示采用直链还是转发，以及播放过程中发生的方式变化。原先“网页和飞牛统一由 Rust 转发媒体”的建议撤回。

用户原话：“q13:优先给直链，迫不得已才做转发，并在播放日志中显示直链还是转发”。

直链指媒体由客户端从视频源获取。服务端签发播放会话、提供播放信息或进行少量可用性检查，不代表其转发了媒体，也不能证明客户端已经成功播放。

转发保留原始画质。原生客户端外部地址、HLS 与必要回退能力仍作为先行验证项目，实际的播放协商字段与结果以本机验证确定。

### Q14：账号创建与管理

已确认：首次部署由使用者设置管理员账号；其他账号由管理员创建，普通用户可修改自己的密码。网页和飞牛使用同一套账号。提供管理员密码的本机恢复操作。

### Q15：部署组成与数据

已确认：使用单容器提供 Rust 服务与网页，SQLite 和持久化数据卷保存账号、配置、目录与个人观看状态；提供 Docker Compose 配置，覆盖 x86_64 与 ARM64 镜像构建。容器重建继续使用既有数据，备份通过一致性数据库备份与对应数据文件完成。

## 第四轮新增分支：直链优先与播放日志

Q13 的方向已经确认。本轮只补充直链优先引出的实际行为；第三轮其他尚未回答的项目继续保留原建议。

### Q16：必要转发的触发条件

已确认：默认先向客户端提供直链，遇到明确的连接、跨域或必要请求条件问题，且转发有望解决时再回退；避免因普通暂停、拖动、用户取消或媒体解码不支持而切换转发。网页可依据播放器反馈自动回退一次，并保留用户主动重试入口。

飞牛是否能自动反馈直连失败、能否通过原生重试改用转发，需依据兼容协议和本机行为核验。如果无法获取足够证据，不凭服务端猜测把整类源长期设为转发；提供明确的手动转发重试入口，并在验收中说明其所在位置。手动重试作用于当前播放，不默默改变整个源的默认策略。

当前只读调查未证明飞牛存在可供自动回退使用的失败回传。服务端一段时间没有收到进度，不等于直连失败；服务端自身探测结果也不等于客户端网络的实际结果。

### Q17：播放日志

已确认：在网页提供可查看的播放日志，记录时间、用户与客户端、影片与集数、来源、直链或转发方式、切换原因以及可观察到的结果。同一观看过程的回退经过关联展示。管理员可查看全部，普通用户仅查看自己的记录；默认保留 30 天。

必须区分“已提供直链”和“已观察到播放进度”，不能把返回播放地址记作播放成功；若只转发部分 HLS 资源，应标明实际转发范围。日志不保存带凭据的完整链接。

单次非零进度可能是定位或拖动；即使持续上报推进，也只能描述客户端上报的进度。画面和声音的实际播放验收需使用本机观察，不能由日志字段替代。直链无回传时结果保持未知；转发开始返回字节也不直接等于客户端解码成功。

## 整体实施与验收

先前已确定的要求与后续选择共同构成实施方案。2026-11-12 用户确认所有剩余项并要求增加禁止转发设置，设计已获得整体确认，进入实现。

实施先后依据兼容风险安排：先跑通飞牛登录、目录、原生搜索、外部直链和可拖动的 HLS 播放，并确认必要回退及日志观测，再补齐订阅、聚合检索、个人数据、网页交互、管理功能与 Docker 交付。原生接口细节以本机观察修正；发现必须改变已确认产品范围时重新记录决策。

网页使用中文，适配桌面与手机浏览器。页面包括首次设置、登录、首页推荐、搜索、影片详情、选集播放、个人收藏与历史，以及管理员账号和配置管理；播放日志提供网页入口。源列表为空、部分源超时、推荐服务失败、订阅更新失败、影片不可播放时都有明确状态和可执行入口。

验收至少覆盖：

- 首次启动源列表为空，管理员可导入 JSON、Base58 和订阅 URL；无效更新不会覆盖当前可用配置。
- 聚合搜索在部分源失败时仍返回其他源结果；源详情、剧集列表与选集保持正确关联。
- 网页实际播放 MP4 与 HLS，验证暂停、拖动、选集和续播。
- 对网页与飞牛分别核验直链优先：直接播放时由客户端访问媒体来源，不以本项目持续转发媒体；必要回退时日志记录方式变化和原因。
- 日志应区分地址交付、观察到播放、回退和失败；受控失败用例验证回退条件，不将无法观测的直接播放结果报告为成功。
- 本机飞牛播放器实际添加服务器、登录、浏览、搜索、查看电影与剧集、播放 HLS、拖动与退出续播。
- 同一用户网页与飞牛的收藏、进度一致，不同用户的数据彼此隔离。
- Docker 服务重启和容器重建后，账号、导入配置及个人数据保留；数据可备份恢复。
- 本地可重复的受控媒体用于定位兼容问题，同时对指定仓库的实际配置做有限集成验证；分别记录协议测试、实际源访问和原生客户端的结果。
- 测试通过范围按实际证据记录，不能用相邻项目记录、接口单测或网页播放替代本项目原生客户端验收。

## 全局禁止转发

已确认：增加管理员设置“禁止转发”。开启后仅交付直链，直连失败时明确提示；自动回退、手动转发、原生客户端请求及既有转发地址都服从该设置。开启设置同时停止正在进行的媒体转发，已在客户端缓冲的媒体可能继续播放短暂时间。默认关闭此强制开关，正常策略仍为直链优先、必要时回退。播放日志记录被禁止的回退或转发请求。
