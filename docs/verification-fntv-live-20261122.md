# 实源压缩清单、图片头分片与账号删除验收

日期：2026-11-22，Asia/Shanghai。用户报告新版开启禁止转发后，飞牛播放“豺狼的日子”第 1 集仍提示 `STRM 直连播放异常（-99985）`，提供测试服务用于排查，并要求增加删除用户功能。

## 真实故障

使用获授权的测试账号登录用户服务，确认禁止转发开启。读取截图对应的爱奇艺来源第一集，并在本机飞牛播放器 **1.13.0 / 1130013**、Mac 的 iOS 兼容环境中复现相同错误。

该来源实际返回 HLS 清单，HTTP 使用 gzip 或 Zstandard 压缩。原有上游客户端没有解压，缓存将压缩后的内容标为普通文件，飞牛拿到 `.mp4` 交付及“画质待识别”。真实清单的分片地址以 `.png` 结尾，分片前有 **181 字节 PNG 图片头**，后面是 H.264／AAC MPEG-TS。仅修复探测或清单压缩仍不足以保证飞牛实际解码。

独立 FFprobe 同样拒绝原始图片扩展名。`.ts` 重定向解决扩展名检查，但飞牛仍不能直接解码图片头。因此，需要客户端按 HLS 字节区间跳过图片头。保留原视频编码、分辨率和帧率，未关闭用户服务的禁止转发设置。

## 修复行为

- 上游请求支持 gzip、Brotli、deflate 和 Zstandard 解压；大小限制应用于解压后的内容。
- `.m3u8` 或 HLS 线路下，未识别为视频的旧文件缓存重新探测。
- 禁止转发时交付解压后的完整清单，主清单、子清单及音频清单安全关联当前账号与播放会话；媒体 URI 使用绝对地址。
- 图片扩展名的 TS 分片使用带 `.ts` 后缀的短期地址，仅返回重定向。未加密且没有既有区间的分片，先有界读取 **最多 4 KiB**，确认连续 TS 同步字节、总长度及上游 206 支持，再声明 `EXT-X-BYTERANGE` 并将清单版本至少设为 4。客户端从上游直接读取视频区间。
- 既有字节区间与加密语义保留；无法确认区间的来源报错并提示换源，不自动转发。区间缓存一小时，最多 64 个识别请求并行，资源按播放会话集中登记。
- 本站登录头留在本站；携带认证头的媒体入口继续遵守禁止转发规则。

## 删除用户

管理员通过 `DELETE /api/users/{id}` 删除其他成员，网页“家庭账号”提供删除按钮及明确的永久删除确认提示。操作在写事务中重新验证管理员及其会话，禁止删除当前管理员；并发删除彼此的管理员仍保留一个有效管理员。

用户外键级联清理登录会话、偏好、收藏、进度、订阅授权、播放会话、播放日志、媒体资源、飞牛菜单与 SDK 绑定。提交事务后通知播放中的资源流停止。回归实际构造上述数据与等待中的媒体流，确认删除后旧登录／媒体能力失效、数据清理、外键完整及其他成员记录保留。

## 2026-11-23 公网入口后续失败

用户仍报告第一集 `STRM 直连播放异常（-99985）`。使用已授权的测试账号复查爱奇艺线路：线上网页已包含删除用户，播放协商交付空请求头的 `.m3u8`，视频识别为 1920×1080 H.264，说明上轮改动已在实际响应中生效。

该线路的公网 HLS 入口连续三次返回 **400**，响应为“上游连接、读取或证书验证失败”。另一条 HLS 来源的公网清单返回 **200**。强制重新探测同一爱奇艺单集也取得 **1080p H.264 / 25 fps**；本机对 853 个图片头分片逐个有界检查，均返回有效 **206** 区间。本轮先修正批量识别期间的连接处理，并补充失败阶段。服务器底层失败原因仍需结合新版服务日志确认。

上轮实现每个分片重新建立上游客户端，每张清单最多并发 64 个请求；多个播放可叠加。任意一次连接失败就终止整张清单。受控对照复现旧版 **400**：顺序读取四个资源建立四个连接，两个清单在临时分片失败和上游并发限制下无法完成；新版通过相同类型的回归。

本轮调整：

- 每次请求和重定向先重新解析、验证 DNS，只有地址集合相同时复用已固定地址的连接池。连接池有数量及过期上限，本站认证头继续过滤。
- 全服务最多 **32 个分片识别请求**同时执行。GET／HEAD 的短暂连接失败有一次有界重试，分片的临时 HTTP 错误可重试一次；失效地址不自动重试，禁止转发设置继续生效。
- 分片缓存按批读取，在一次事务中提交已完成结果，失败后可复用已确认的部分。完整清单仍声明真实字节区间，保留原有加密与区间语义。
- “播放日志 → 查看过程”记录清单读取或分片识别阶段的失败；服务日志保留去除 URL 的网络错误，避免把真实媒体地址或令牌写入错误说明。
