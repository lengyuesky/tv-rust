# 飞牛 HLS 交付与实测画质验收

日期：2026-11-22，Asia/Shanghai。用户报告《午夜规则》第五集在飞牛提示直连异常 `-99985`，所有来源不能播放，并要求视频质量菜单显示“源名称 · 实际画质”。本轮在 `main` 上修复，不修改用户运行中的部署或生产数据库。

## 故障与修复

使用已发布的 `fbc665a` 作为旧版，在独立数据库、相同客户端与正常本地 HLS 下实际复现 `-99985`。旧版向 HLS 返回网盘原文件通道及无后缀的来源地址；修复后 HLS 使用原生清单通道，`cloud_storage_info` 为空、清单地址带 `.m3u8`，认证 Range 获取完整清单。MP4 继续使用 STRM 直链，来源菜单地址保留媒体后缀。

参考 [fnmedia-ext 的固定版本](https://github.com/funwukong/fnmedia-ext/tree/eaf4a535d54c9d760358c8efd923d7dfe644052e) 中 `play_play`、`media_range`、`media.resetQuality` 和清晰度菜单：HLS 的原生 `play/play` 交付同站相对地址，来源以原生清晰度选择码定位。未配置 `TV_PUBLIC_URL` 时正确使用反向代理协议及主机地址；密钥和分片使用完整本站资源地址，所有上游请求继续过滤本站登录头。

实际换源时观察到客户端先申请新播放，随后上报旧 SDK UUID 的 `play/quit`。旧 UUID 曾误结束新来源，已以独立持久关联区分菜单和具体播放会话。原位 RPC 换源保留并更新该 SDK 身份，API 换源保留旧身份以拦截旧退出和进度。新关联与资源解密字段由第六次数据库迁移自动添加，保留既有作品身份、个人记录和来源权限。

当前客户端读取受控 AES-128 清单和完整正确密钥后仍失败；独立 FFmpeg 能解码同一资源。必要原生转发改为流式 AES-128 CBC 分片解密，保留原始编码、尺寸和帧率，不转码或缓存整部影片。隐式 IV 使用实际媒体序号，显式 IV、密钥及分片身份分别处理，结束时验证 PKCS#7 填充。完整分片 AES-128 已验证；SAMPLE-AES、DRM、加密字节区间明确报不支持，没有当成普通 AES-128 处理。

视频质量菜单单行显示 `源名称 · 1080p`，按实际尺寸从高到低排列，同源多线路仍可区分，未知画质明确标识。原生菜单的整数 `bitrate` 是选择码；客户端可能把它格式化为 Mbps，它不代表实测码率。真实码率和完整画质字段仍由媒体详情的探测结果提供。

## 自动验证

Rust 集成测试 **55 项**、AES 标准向量及 IV 单元测试 **2 项**，共 **57 项**通过；Clippy、格式及本地构建通过。前端既有 **13 项**测试及 TypeScript／Vite 构建通过。

- 原生 HLS 起播模型、媒体后缀、反向代理 HTTPS 地址、稳定清单及原生当前来源解析。
- 原生 NAS 转发入口、重复 Range 不替换进度关联、全局禁止转发及认证 HEAD 限制。
- SDK UUID 进度、同作品单集身份、RPC 换源、换回旧线路、API 换源后的旧退出通知及旧进度、删除后迟到回传、主动重新起播和账号隔离。
- AES CBC 的 NIST 向量、非整块网络分片、截断与无效填充、显式／隐式 IV。实际加密 MPEG-TS 经转发解密后由独立 FFprobe 确认 H.264、64 × 64 及完整视频包。
- 探测确认媒体 404／410 时在起播前明确失败；目标失效不会结束旧来源。既有订阅授权、作品去重、删除事务、媒体资源总量和并发回归继续通过。

## 本机客户端实测

使用飞牛播放器 **1.12.3 / 1123003**，运行于本机 Mac 的 iPhoneOS 兼容环境。连接独立本地服务及测试数据库，受控源包含普通 360p、AES-128 加密 720p、普通 1080p HLS 和 MP4。

- 普通 1080p HLS 实际显示蓝色画面，修复后没有旧版 `-99985`，SDK UUID 的实际进度写入对应播放会话。
- 单源 AES-128 HLS 通过原生转发解密实际显示绿色 720p 画面，取得九次进度回传。
- 播放中实际打开视频质量菜单，看到 `本地源C · 1080P`、`本地源B · 720P`、`本地源A · 360P`，按高到低排列。选中 B 后实际画面从蓝色变绿色；新播放存活，取得八次进度回传并归入源 B。客户端旧退出通知没有结束新来源。
- MP4 直链实际显示源 C 的蓝色 1080p 画面；夹具收到 `trim_player` 对原 MP4 的 Range 请求，不包含 Cookie、Authorization 或 Authx。本轮没有重新计入 MP4 播放中二次换源的手动验收，相关协议回归及此前实际结果继续保留。
- 夹具所有媒体请求中本站登录头泄露数为 **0**。来源权限、跨源独立进度及删除记录防回写由上述自动测试验证。

证据目录：`tmp/fntv-delivery-20261122-7FoL1z/`。截图为 `native-final-quality-menu.png`、`native-hls-final-1080p.png`、`native-aes128-720p.png`、`native-hls-switch-720p.png` 和 `native-mp4-1080p.png`；`native-final-evidence.json` 汇总进度与请求，`native-requests.jsonl`、`media-requests.jsonl` 和 `server-final-decrypted.log` 保留对照过程。旧版错误截图为 `tmp/fntv-delivery-20261121/baseline-hls-99985.png`。临时客户端与服务在发布前停止。
